# 要件定義書 — GazePause

## 1. 概要

| 項目 | 内容 |
|---|---|
| プロジェクト名 | GazePause |
| 種別 | Chrome拡張機能 |
| 目的 | ユーザーがテレビ(画面)から視線を外した際、再生中の動画を自動で一時停止する |
| 対象サイト | YouTube, Amazon Prime Video |
| 開発形態 | 個人開発 |

## 2. 背景・課題

- 動画視聴中に離席・よそ見をしても再生が進み続け、見逃しや巻き戻しの手間が発生する。
- 手動での一時停止操作を省略し、視線に応じて自動化したい。

## 3. スコープ

### 3.1 対象とする範囲(In Scope)

- Chrome上でのYouTube再生の一時停止/再開制御
- Chrome上でのAmazon Prime Video再生の一時停止制御(再開は要検証)
- Webカメラ映像からの顔向き検出による「視聴中/非視聴中」の判定
- 誤検知を抑制するための判定ディレイ・しきい値調整機能

### 3.2 対象としない範囲(Out of Scope)

- Chrome以外のブラウザ対応(Safari, Edge, Firefox等)
- YouTube / Prime Video以外のサービス(Netflix, Disney+等)は初期スコープ外
- 眼球運動(gaze)レベルの高精度視線推定(初期版は顔の向きのみで判定)
- モバイル・タブレット環境への対応
- 複数人が同時に映る環境での個人識別

## 4. 用語定義

| 用語 | 定義 |
|---|---|
| 視聴中 | 顔がカメラ(=テレビ方向)を向いている状態 |
| 非視聴中 | 顔がカメラから一定角度以上逸れている状態が、しきい値フレーム数以上継続した状態 |
| 判定ディレイ | まばたきや一瞬の首振りによる誤検知を防ぐための、状態確定までの猶予フレーム数/時間 |
| content script | 対象ページのDOMに注入され、video要素を直接操作するスクリプト |
| background service worker | 拡張機能全体を裏側で管理し、メッセージを中継する常駐スクリプト |
| offscreen document | Manifest V3において、DOM非依存の処理(映像解析等)をバックグラウンドで行うための隠しページ |

## 5. 機能要件

### 5.1 顔向き検出

| ID | 要件 |
|---|---|
| F-01 | Webカメラ映像を取得し、リアルタイムで顔のランドマークを検出できること |
| F-02 | 顔がカメラ方向を向いているか否かを判定できること |
| F-03 | 連続Nフレーム(可変)以上「非視聴」状態が継続した場合のみ、状態を確定させること |
| F-04 | 顔が検出できない場合(カメラ範囲外、遮蔽等)の扱いを定義すること(初期実装では「非視聴」扱いとする) |

### 5.2 動画再生制御

| ID | 要件 |
|---|---|
| F-10 | 「非視聴」確定時、アクティブタブの動画を一時停止すること |
| F-11 | 「視聴」状態に復帰した際の挙動(自動再開 or 手動)を設定で切り替えられること |
| F-12 | YouTubeの`<video>`要素に対してpause/play操作ができること |
| F-13 | Amazon Prime Videoの`<video>`要素に対してpause操作ができること(DRM環境下での動作検証を含む) |

### 5.3 設定・UI

| ID | 要件 |
|---|---|
| F-20 | カメラ使用の許可/停止をユーザーが切り替えられること |
| F-21 | 判定感度(しきい値、ディレイ時間)を設定画面から調整できること |
| F-22 | 一時停止が発生したことをユーザーに視覚的に通知すること |

## 6. 非機能要件

| ID | 分類 | 要件 |
|---|---|---|
| N-01 | パフォーマンス | 顔検出処理がブラウザの動画再生を阻害しない負荷であること(CPU使用率を許容範囲に抑える) |
| N-02 | プライバシー | カメラ映像・顔データを外部送信しないこと(すべてローカル処理で完結) |
| N-03 | 権限 | manifest.jsonで要求する権限は必要最小限とすること |
| N-04 | 誤動作耐性 | 誤検知による意図しない一時停止の頻度を実用上許容できる水準に抑えること |
| N-05 | 保守性 | content script / background / 判定ロジックを役割ごとに分離した構成とすること |

## 7. 制約条件

- Manifest V3準拠(Chrome Web Storeの現行仕様)
- カメラ映像処理はブラウザ内(クライアントサイド)で完結させ、外部サーバーを持たない
- Amazon Prime VideoはDRM(Widevine)保護コンテンツのため、video要素への操作可否は実機検証が前提
- 開発者は本プロジェクトが対象言語(JavaScript/TypeScript)の実務経験が浅いため、段階的な学習を伴う開発となる

## 8. 前提条件

- 検証初期段階ではノートPC内蔵カメラを使用し、外付けWebカメラは後続フェーズで導入する
- 対象OSはWindows(開発者の主環境)を基準とするが、Chrome拡張機能である以上、原則クロスプラットフォームで動作する想定

## 9. リスク・未検証事項

| リスク | 内容 | 対応方針 |
|---|---|---|
| DRM制約 | Prime VideoでのDRM保護によりvideo要素操作が制限される可能性 | 早期(フェーズ3以降)に実機検証し、代替手段(プレイヤーUI操作等)を検討 |
| Manifest V3のカメラ制約 | content script単体ではカメラ処理がしにくく、offscreen documentが必要になる可能性 | 骨組み設計時に前提として組み込む |
| 誤検知 | 照明条件・カメラ設置角度により判定精度が変動する | しきい値・ディレイを可変パラメータとして設計 |

## 10. マイルストーン(概略)

1. 顔向き検出のPoC(拡張機能化前)
2. 判定ロジックの調整
3. 拡張機能骨組み作成(manifest.json / background / content script)
4. YouTubeでの再生制御実装
5. カメラ処理の統合設計(offscreen document対応)
6. Prime Videoでの動作検証
7. UI/UX仕上げ

詳細な構成・技術設計は `architecture.md` を参照。
